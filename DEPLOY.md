# Deploying (Vercel + Render + Upstash)

> **This setup is not free** — Render background workers are paid. For a $0 deployment that runs
> the whole stack, see [DEPLOY-ORACLE.md](DEPLOY-ORACLE.md).

The app is five processes, so it is split like this:

| Part | Host |
|---|---|
| frontend | Vercel |
| primary-backend, hooks | Render web services |
| processor, worker | Render background workers |
| Postgres | Render Postgres |
| Kafka | Upstash Kafka |

`render.yaml` in the repo root describes everything except the frontend and Kafka.

## 1. Upstash Kafka

1. Open https://console.upstash.com/kafka and create a cluster (free tier is fine).
2. Create a topic named `zap-events`.
3. Copy from the cluster page:
   - **Endpoint** (looks like `xxx-xxx.upstash.io:9092`)
   - **Username**
   - **Password**

## 2. Render

1. Push this repo to GitHub (already done).
2. Render dashboard → **New → Blueprint** → pick the repo → **Apply**.
3. Render creates the database and four services. It asks for the values marked `sync: false`:

| Service | Variable | Value |
|---|---|---|
| zapier-api | `SMTP_ENDPOINT` | `smtp-relay.brevo.com` |
| zapier-api | `SMTP_PORT` | `587` |
| zapier-api | `SMTP_USERNAME` | your Brevo SMTP login |
| zapier-api | `SMTP_PASSWORD` | your Brevo SMTP key |
| zapier-api | `SMTP_FROM` | your verified sender |
| zapier-processor, zapier-worker | `KAFKA_BROKERS` | Upstash endpoint |
| zapier-processor, zapier-worker | `KAFKA_SASL_USERNAME` | Upstash username |
| zapier-processor, zapier-worker | `KAFKA_SASL_PASSWORD` | Upstash password |
| zapier-worker | `SMTP_*` | same as the API |
| zapier-worker | `SOL_PRIVATE_KEY` | wallet secret (base58) |
| zapier-worker | `SOLANA_RPC_URL` | your devnet RPC url |

`JWT_PASSWORD` is generated by Render, `SOLANA_DRY_RUN` stays `true`.

4. Leave `FRONTEND_URL` empty for now and do step 4 first if Render asks.

## 3. Seed the database

Render dashboard → `zapier-api` → **Shell**:

```bash
npx prisma db seed
```

This creates the `webhook`, `send-sol` and `email` rows. Run it once.

## 4. Vercel

1. Vercel → **Add New → Project** → import the same repo.
2. **Root Directory:** `frontend` (important, the repo root is not a Next.js app).
3. Framework is detected as Next.js; leave build settings alone.
4. Environment variables:

```
NEXT_PUBLIC_BACKEND_URL = https://zapier-api.onrender.com
NEXT_PUBLIC_HOOKS_URL   = https://zapier-hooks.onrender.com
```

(use the real URLs Render shows for your services)

5. Deploy.

## 5. Close the loop

Back in Render → `zapier-api` → Environment → set:

```
FRONTEND_URL = https://your-app.vercel.app
```

Save (Render redeploys). Verification and password reset emails now link to Vercel.

## 6. Check it

```
https://zapier-api.onrender.com/health      -> {"status":"ok"}
https://zapier-hooks.onrender.com/health    -> {"status":"ok"}
https://your-app.vercel.app                 -> the app
```

Sign up, open the verification email (check spam), then create a zap and hit its webhook.

## Things to know

- **Free web services sleep** after 15 minutes. The first request afterwards takes ~30s. Webhooks and email links will feel slow until it wakes.
- **Background workers are not free** on Render (starter plan, about $7/month each). Processor and worker must stay running or Solana/email actions never execute.
- **Render's free Postgres expires after 90 days.**
- Keep `SOLANA_DRY_RUN=true` until you are ready to move real SOL.
