# Deploy for free, with no credit card

Everything below is on free plans that **do not ask for a card**. Nothing runs on your computer.

| Part | Where | Card |
|---|---|---|
| frontend | Vercel (Hobby) | no |
| `primary-backend` (API) | Render free web service | no |
| `hooks` (webhooks) | Render free web service | no |
| Postgres | Supabase free / Neon free | no |
| `processor` + `worker` | GitHub Actions, every 5 minutes | no |
| mail | Brevo HTTPS API | no |

How the last row works: instead of two always-on processes waiting on Kafka, a scheduled GitHub
Action runs `worker/dist/once.js`, which takes the pending rows from `ZapRunOutbox`, executes the
actions in order and exits. Same code, same tables, same Solana/email logic — just triggered on a
timer. Kafka is not used in this setup (it is still used by `docker compose` locally).

---

## 1. Database — Supabase (free)

1. https://supabase.com → sign up with GitHub → **New project**. Pick a region near you, set a
   database password and save it.
2. Wait ~2 minutes for provisioning.
3. **Project Settings → Database → Connection string → URI**. Choose the **Session pooler** tab
   (not "Direct", it is IPv6-only and Prisma on Render cannot reach it).
4. Copy it and replace `[YOUR-PASSWORD]` with the password from step 1. It looks like:

```
postgresql://postgres.abcdwxyz:YOUR-PASSWORD@aws-0-ap-south-1.pooler.supabase.com:5432/postgres
```

> Neon also works (no card) but its free plan counts compute hours, and a worker that wakes the
> database every 5 minutes can use them up mid-month. Supabase has no such meter.

## 2. Mail — Brevo API key

Render's free plan blocks outbound SMTP (ports 25/465/587), so the API and worker send over
Brevo's HTTPS API. You already have a Brevo account.

1. https://app.brevo.com → top right menu → **SMTP & API → API Keys → Generate a new API key**.
2. Copy it (`xkeysib-...`). This is **not** the SMTP password.

## 3. API + hooks — Render

1. https://dashboard.render.com → sign up with GitHub (no card).
2. **New → Blueprint** → select the `zapier` repo → **Apply**.
   `render.yaml` creates `zapier-api` and `zapier-hooks` on the free plan.
3. Render asks for the values marked as secret:

| Service | Variable | Value |
|---|---|---|
| zapier-api | `DATABASE_URL` | the Supabase **session pooler** string |
| zapier-api | `FRONTEND_URL` | leave for now, filled in step 5 |
| zapier-api | `BREVO_API_KEY` | from step 2 |
| zapier-api | `SMTP_FROM` | your verified sender, e.g. `naveenmallada369@gmail.com` |
| zapier-api | `SMTP_ENDPOINT` / `SMTP_PORT` / `SMTP_USERNAME` / `SMTP_PASSWORD` | optional, leave empty |
| zapier-hooks | `DATABASE_URL` | same Supabase string |

`JWT_PASSWORD` is generated by Render automatically.

4. Wait for both to go live. Their URLs look like `https://zapier-api.onrender.com` and
   `https://zapier-hooks.onrender.com`. The API's start command already runs
   `prisma migrate deploy`, so the tables are created on the first boot.
5. Check: `https://zapier-api.onrender.com/health` → `{"status":"ok"}`. The first hit after 15
   idle minutes takes ~1 minute (free services sleep).

### Seed the trigger/action list (once)

Render dashboard → `zapier-api` → **Shell**:

```bash
npx prisma db seed
```

Expected: it prints the created `webhook` trigger and the `send-sol` / `email` actions.

## 4. Frontend — Vercel

1. https://vercel.com → sign up with GitHub → **Add New → Project** → import the repo.
2. **Root Directory: `frontend`** (the repo root is not a Next.js app).
3. Framework preset: Next.js. Leave the build settings alone.
4. **Environment Variables** (Production):

```
NEXT_PUBLIC_BACKEND_URL = https://zapier-api.onrender.com
NEXT_PUBLIC_HOOKS_URL   = https://zapier-hooks.onrender.com
```

5. **Deploy**. You get `https://<project>.vercel.app`.

## 5. Point the API back at the frontend

Render → `zapier-api` → **Environment** → set `FRONTEND_URL` to your Vercel URL
(`https://<project>.vercel.app`) → save (Render redeploys).

Verification and password-reset emails now link to the Vercel app.

## 6. The worker — GitHub Actions

File: `.github/workflows/run-zaps.yml` (already in the repo).

1. GitHub → repo → **Settings → Secrets and variables → Actions → New repository secret**:

| Secret | Value |
|---|---|
| `DATABASE_URL` | Supabase session pooler string |
| `BREVO_API_KEY` | from step 2 |
| `SMTP_FROM` | your verified sender |
| `SOLANA_RPC_URL` | your devnet RPC url |
| `SOLANA_DRY_RUN` | `true` |
| `SOL_PRIVATE_KEY` | optional, only when you stop dry-running |

2. GitHub → **Actions** → **Run pending zaps** → **Run workflow** to test it immediately. A green
   run with `0 pending zap run(s)` means it connected to the database and found nothing to do.
3. After that it runs by itself every 5 minutes.

Notes:
- Scheduled workflows only run on the **default branch**.
- On a **public** repo Actions minutes are free. On a private repo, change the cron in the workflow
  to `0 * * * *` (hourly), otherwise the 2000 free minutes run out.
- GitHub pauses schedules after ~60 days without repo activity; any commit (or manual run) wakes it.

## 7. Test the whole thing

```
https://<project>.vercel.app          -> the app
https://zapier-api.onrender.com/health -> {"status":"ok"}
https://zapier-hooks.onrender.com/health -> {"status":"ok"}
```

1. Sign up, wait for the verification mail (Brevo, check spam), click the link.
2. Sign in, create a zap: webhook trigger → send SOL action.
3. The dashboard shows the webhook URL. Fire it:

```bash
curl -X POST https://zapier-hooks.onrender.com/hooks/catch/<userId>/<zapId> \
  -H 'content-type: application/json' -d '{"amount":"0.001"}'
```

4. Within 5 minutes GitHub → **Actions** should show a run that processed it. In Supabase's SQL
   editor: `select status, signature from "ActionExecution";` → `CONFIRMED | dry-run:...`.

## What is different from the local stack

| Local | Hosted |
|---|---|
| Kafka + processor + worker | outbox → GitHub Action every 5 min |
| Postgres container | Supabase |
| Caddy | Render/Vercel HTTPS |
| SMTP (port 587) | Brevo HTTPS API (`BREVO_API_KEY`) |

`docker compose` still works exactly as before; nothing in the local setup changed.

## Honest limits of the free stack

- **Zaps run up to 5 minutes late.** GitHub's cron minimum is 5 minutes and runs can be delayed.
- **Render sleeps after 15 idle minutes**; the next request takes ~1 minute. A webhook that arrives
  while `zapier-hooks` is asleep can time out for the caller (the row may still be written).
- **750 Render instance hours/month** — both services together are fine as long as they sleep
  (do not add uptime pingers, that burns the hours twice as fast).
- **Supabase free**: 500 MB database, 5 GB egress, project pauses after 7 days with no traffic
  (the 5-minute worker keeps it awake).
- **Vercel Hobby** is for non-commercial projects. Fine for a demo/portfolio link.
- **`SOLANA_DRY_RUN`** is dry unless it is explicitly `false`, so no SOL can move by accident.

## If something is wrong

| Symptom | Cause | Fix |
|---|---|---|
| Render build fails on `prisma migrate` | DATABASE_URL is the IPv6 "direct" string, or the password is wrong | use the session pooler URI, replace `[YOUR-PASSWORD]` |
| signup returns 500 | `BREVO_API_KEY` missing/invalid → mail throws | set the key, check `SMTP_FROM` is a verified sender |
| emails never arrive | sender not verified in Brevo, or API key wrong | Brevo → Senders, verify the address |
| frontend calls `localhost` | `NEXT_PUBLIC_*` not set before the Vercel build | set them, then **Redeploy** |
| dashboard webhook URL is wrong | `NEXT_PUBLIC_HOOKS_URL` must be the Render hooks URL | fix, redeploy |
| action stays PENDING | workflow not enabled / secrets missing | Actions → Run workflow, read the log |
| first request takes a minute | Render free service woke up | expected |
